Introduction

AI is rapidly becoming part of everyday applications - but how can Java developers actually use it in real-world systems?

In this hands-on workshop, we'll build an intelligent "Meetup Community Assistant" using Spring Boot, exploring how modern AI capabilities can be integrated directly into your backend services.

Starting from a simple Spring Boot application, we'll progressively evolve it into a fully capable AI agent that can understand user intent, interact with business logic, and automate workflows like event RSVPs.

What You'll Learn

  • How to use Spring AI in real applications
  • Integrating LLMs into Spring Boot APIs
  • Structured output - getting typed Java objects from AI responses
  • Function calling - letting the AI invoke your business logic
  • Chat memory - maintaining conversational context
  • Exposing your application via MCP (Model Context Protocol) for external integrations

💡 Tip

If you use PowerShell and IntelliJ often, you can set up a handy alias that extracts and opens in one command. Add this function to your PowerShell profile ($PROFILE):

# idea - Extract a Spring Initializr zip and open it in IntelliJ IDEA
# Usage: idea <zip-file> [destination]
function idea {
    param(
        [string]$ZipPath,
        [string]$Dest = "C:\Development\Code"
    )
    $name = [System.IO.Path]::GetFileNameWithoutExtension($ZipPath)
    $target = Join-Path $Dest $name
    Expand-Archive -Path $ZipPath -DestinationPath $Dest
    & "idea64.exe" $target
    Remove-Item $ZipPath
}

Step 1 Simple Chat with ChatClient

In this step we add Spring AI to the project and create our first AI-powered endpoint. With just a few lines of code, we'll be talking to an LLM from a Spring Boot controller.

Documentation

  • Spring AI OpenAI docs (dependencies, properties, models, defaults)
  • Spring AI Anthropic docs

Add Spring AI Dependencies

Add the Spring AI BOM and the OpenAI starter to pom.xml:

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>1.0.8</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-starter-model-openai</artifactId>
</dependency>

Configure the API Key

⚠️ Important

API keys should always be injected via environment variables - never hardcoded in source files. If the API key is not set, the application will fail to start with: OpenAI API key must be set

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY} # always inject from env vars
      chat:
        options:
          model: gpt-4o-mini
Setting OPENAI_API_KEY in IntelliJ Run Configuration

Add the /chat Endpoint

@RestController
public class JavaController {

   private final ChatClient chatClient;

   public JavaController(ChatClient.Builder builder) {
      this.chatClient = builder.build();
   }

   @GetMapping("/chat")
   public String chat(@RequestParam String message) {
      return chatClient.prompt()
            .user(message)
            .call()
            .content();
   }
}

5 lines to talk to an LLM.

📝 Note on AiConfig

When you only have a single AI provider in your dependencies, Spring AI auto-configures a default ChatClient.Builder bean. No AiConfig class needed. However, with multiple providers (OpenAI + Anthropic), you'll need to explicitly specify which ChatModel to use.

ChatClient responding to "Hi from SKG Java Meetup!"

Add a System Prompt

A system prompt sets the AI's personality and behavior for all interactions:

public JavaController(ChatClient.Builder builder) {
   this.chatClient = builder
         .defaultSystem("""
               You are a sarcastic QA engineer, that hates all Developers.
               Speak only with riddles and be rude. Be direct and short.
               """)
         .build();
}
"What's more pointless than a meeting of minds that can't even meet a deadline?"

Prompt Decoration

Enhance individual request prompts with additional context using parameterized templates:

@GetMapping("/chat/suggest")
public String suggestion(@RequestParam String message) {
   return chatClient.prompt()
         .user(u -> u.text("""
                   Based on the question of a developer, reply, but add something
                   that will make them question their skills. ...
                   Developer's Question: {message}
                   """).param("message", message))
         .call()
         .content();
}
Decorated prompt combining system persona with per-request instructions
💡 Key Takeaway

The system prompt sets the overall personality, while prompt decoration shapes individual requests. Together, they give you fine-grained control over AI behavior without changing any model settings.

Step 2 Structured Output

What if you want the response as a typed Java object instead of raw text? Spring AI makes this remarkably simple.

Define the DTOs

record ProgrammingLanguageDTO(String name, String creator, LocalDate createdAt, Double popularity) {}
record ProgrammingLanguageSuggestion(String reason, ProgrammingLanguageDTO language) {}

Swap .content() for .entity()

The key change is just one line:

.call()
.entity(ProgrammingLanguageSuggestion.class);

How It Works Behind the Scenes

  1. Schema generation: Inspects the Java record and generates a JSON Schema
  2. Prompt augmentation: Appends the schema as instructions to the prompt
  3. Deserialization: The LLM's JSON response is deserialized via Jackson
No parsing. No regex. A typed Java record, straight from the AI.
📝 More Info

See the official docs on Structured Output Converters for details.

Step 3 Chat Memory

So far, every request is stateless. In this step, we add conversational memory so the AI can maintain context across requests.

Add the MessageChatMemoryAdvisor

public JavaController(ChatClient.Builder builder,
                      ChatMemory chatMemory) {
   this.chatClient = builder
         .defaultSystem("""...""")
         .defaultAdvisors(new SimpleLoggerAdvisor(),
               MessageChatMemoryAdvisor.builder(chatMemory).build())
         .build();
}

Use conversationId

.advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
First request: AI suggests HTML as the "worst" frontend language
Follow-up: AI remembers it recommended HTML and defends its choice
⚠️ LLMs Do Not Remember Anything

LLMs are stateless. Chat memory is an illusion - Spring AI stores all previous messages locally and replays the entire conversation history in every new request. This comes with trade-offs:

  • Token cost: Every previous message is re-sent on every call
  • Context window limits: Long conversations will exceed the limit
  • Hallucination risk: Longer context leads to more contradictions

This is why MessageWindowChatMemory uses a sliding window (maxMessages). Use chat memory intentionally.

Persisting Chat Memory

By default, memory uses InMemoryChatMemoryRepository (a ConcurrentHashMap, lost on restart). To persist, add one of:

  • JDBC - spring-ai-starter-model-chat-memory-repository-jdbc
  • Cassandra - CassandraChatMemoryRepository
  • Neo4j - Neo4jChatMemoryRepository

Source: Chat Memory :: Spring AI Reference

Step 5 Tool Calling / Function Calling

This is the centerpiece of the workshop. Tool calling lets the AI invoke your actual Java business logic autonomously based on natural language requests.

📝 Official Docs

docs.spring.io/spring-ai/reference/api/tools.html

How Tool Calling Works

The 6-step tool calling flow: Request → AI Model → Dispatch → Tool → Result → Response
  1. Chat Request with Tool Definitions (name, description, input schema) is sent to Spring AI
  2. Spring AI forwards prompt + tool definitions to the AI Model
  3. AI decides to call a tool - Spring AI dispatches the call to the actual Tool
  4. The Tool executes and returns a result
  5. Spring AI sends the tool result back to the AI Model
  6. AI generates the final Chat Response using the tool's data
⚠️ Why Descriptions Matter

@Tool and @ToolParam descriptions are critically important - they are the only way the LLM knows what each tool does and what each parameter means. Think of descriptions as API documentation, but your consumer is an AI, not a human developer.

Create the MeetupTools

@Component
public class MeetupTools {

   private final MeetupService meetupService;

   @Tool(description = "Get all members of the SKG Java Meetup community")
   public List<Member> getAllMembers() {
      return meetupService.getAllMembers();
   }

   @Tool(description = "Search members by name...")
   public List<Member> searchMembersByName(
         @ToolParam(description = "The name or part of the name to search for")
         String name) {
      return meetupService.searchMembersByName(name);
   }

   @Tool(description = "RSVP a member to the next meetup event...")
   public String rsvpToEvent(
         @ToolParam(description = "The email address of the member to RSVP")
         String email) {
      return meetupService.rsvpToEvent(email);
   }
   // + getTopAttendees, getMembersSince, findMemberByEmail
}

Wire It Up

.defaultTools(meetupTools)  // registers all @Tool methods

Step 6 MCP Server

MCP (Model Context Protocol) turns your Spring Boot app into a server that any MCP-compatible AI client can discover and use. Three small changes:

📝 Official Docs

docs.spring.io/spring-ai/reference/api/mcp/mcp-overview.html

1. Dependency:

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-starter-mcp-server-webmvc</artifactId>
</dependency>

2. Configuration:

spring.ai.mcp.server:
  name: skg-java-meetup-mcp
  type: sync
  version: 1.0.0

3. Register tools:

@Bean
ToolCallbackProvider meetupMcpTools(MeetupTools meetupTools) {
   return MethodToolCallbackProvider.builder()
         .toolObjects(meetupTools).build();
}
